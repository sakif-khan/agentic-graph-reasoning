Large language models answer factual questions fluently, but they sound
just as fluent when they are wrong. To fix this, researchers introduced
retrieval-augmented generation, which grounds answers in retrieved text.
But it retrieves only once, so a question spanning several facts is
answered from that one query. Systems that navigate a knowledge graph do
better. They interleave retrieval with reasoning, one hop at a time.
Such a system has several parts. A planner breaks the question into
steps. A scorer picks the next edge. A backtracker recovers from dead
ends. A checker reads the draft answer. Papers report the system as a
whole. So when it beats a baseline, nobody knows which part earned the
gain. We built one, Agentic Graph Reasoning (AGR), with four removable
parts, and took it apart. AGR and four baselines share one frozen
backbone and one call budget on $400$ questions each from WebQSP and
ComplexWebQuestions. AGR leads the agentic baseline by $9.5$ and $8.7$
Hits@1 points. But the whole margin comes from questions where the
shared budget cuts the baseline off. Where it finishes, the baseline is
ahead. Removing the planner improves WebQSP F1 by $0.083$ and cuts token
use by $31\%$. The other three parts, claim verification among them,
show no effect our tests could detect. A hand-read census of the
failures finds label defects in $5.5\%$ and $4.8\%$ of the samples and
names the \emph{echo attractor}. It is a true entity one hop from the
answer, so every grounding check passes it.

\end{abstract}

\section{Prompt templates}
\label{app:prompts}
Seven templates constitute the whole of AGR's interface to the
language model, and six serve the baselines: one for the parametric
control, one shared by the two static retrieval baselines, and four
belonging to the reimplemented agentic baseline. All thirteen are
reproduced here verbatim from the source that sends them, in the
order a question encounters them, by a script that reads the code
(\texttt{scripts/build\_paper\_appendix.py} in the repository named
in the data availability statement). No template carries a
configuration constant, so one cached response serves every
condition of a sweep; budgets are counters in code rather than
instructions, and the evaluator's remaining depth and backtracks are
the only budget figures any prompt carries. Every call asks for JSON
against a schema stated in the code beside the template.

Code, prompts, per-question run records, and the analysis scripts that
produce every figure and table in this paper are available at
\url{https://github.com/sakif-khan/agentic-graph-reasoning} under the
MIT licence. The question sets are the public WebQSP~\cite{yih2016value}
and ComplexWebQuestions~\cite{talmor2018web} releases, and both they
and the Freebase-derived~\cite{bollacker2008freebase} subgraphs arrive
through the public Reasoning-on-Graphs

\textsf{rmanluo/RoG-cwq}), used unmodified. The knowledge environment
is rebuilt from that distribution by the scripts in the repository
rather than redistributed.
